# moonfollow

根据画面中脚步的落点推算 SMPTE 时码，再把脚步声音效按这些时码合成为一条与视频同步的音轨。

<video src="docs/showreel.mp4" controls muted width="640"></video>

62 秒演示——自动配音 / 0.4s 错位修正 / 4% 时钟漂移修正 / 多人 / 侧视 / 不规律脚步。

**项目代码 100% MoonBit**（native 后端）：从视频解码、足部跟踪、落点检测、
时码换算到音频混音全部在 MoonBit 里实现。唯一的非 MoonBit 内容是
MoonBit 官方 native FFI 约定所需的少量 C 胶水（`internal/fsio/stub.c`，
文件读写与子进程管道）；外部工具只依赖系统安装的 `ffmpeg`/`ffprobe`
二进制（视频解码与容器探测，属于运行环境而非项目代码）。

```
video.mp4 --[detect]--> foottrack.json --[steps]--> 落点时码列表
                                              +-- [render] --> footsteps.wav
```

输出的 `footsteps.wav` 拖进 DaVinci Resolve / 任何 NLE，与源片对齐片头即同步。

## 快速体验

```sh
sh examples/demo.sh          # 自包含演示：ffmpeg 合成行走视频 + 脚步声，跑通全流程
sh examples/showreel.sh      # 在 demo 之上拼一支 ~60s 带中文字幕的演示视频（macOS）
```

## 使用

```sh
# 1) 从视频提取足部轨迹（ffprobe 做 CFR 校验，ffmpeg 解码低分辨率灰度帧）
moon run cmd/moonfollow -- detect clip.mp4 -o foottrack.json

# 2) 检测落点 + 渲染音效轨（一步到位）
moon run cmd/moonfollow -- run foottrack.json --sfx step.wav -o footsteps.wav

# 或分步：先核对时码（可修剪 steps.json），再渲染
moon run cmd/moonfollow -- steps foottrack.json -o steps.json
moon run cmd/moonfollow -- render steps.json --sfx step.wav -o footsteps.wav

# 3) 交给剪辑：时码标记导入 Resolve/FCP，或直接把音效轨合成进视频
moon run cmd/moonfollow -- export steps.json -o steps.fcpxml
moon run cmd/moonfollow -- mux clip.mp4 footsteps.wav -o clip-with-steps.mp4

# 4) 原视频已有脚步声但错位？不替换，自动对齐回去
moon run cmd/moonfollow -- align wrong-sync.mp4 -o fixed.mp4
```

`run`/`steps` 打印每个落点的时码、左右脚、强度与帧号：

```text
clip.mp4: 9 steps at 25 fps
00:00:00:20  right  strength 1  frame 20
00:00:01:07  left   strength 1  frame 32
```

29.97/59.94 fps 的素材自动使用 drop-frame 时码（`;` 分隔），25/24/30 等
整帧率使用非丢帧格式（`:` 分隔）。输出为 16-bit PCM、默认 48 kHz、与
视频等长的音轨（末尾音效不截断，音轨可能略长于 `--duration`）。

## 算法（全部 MoonBit 实现）

- **vision/**：ffprobe 探测并拒绝可变帧率 → ffmpeg 解码为小尺寸灰度帧
  （默认 320px 宽，位置只需归一化坐标）→ **像素级时序最小值背景模型**
  （缓慢回升；触地驻留的脚不会污染背景——这正是滑动平均背景的经典败点）
  → 前景行/列直方图求人物框 → 躯干列锚定（**躯干列按宽空隙分组即多人**，
  每人独立 blob 分脚与身份锚点，跨帧按中心稳定关联）→ 每只脚取其最低
  前景行，前景支撑密度作为可见度。`detect --multi` 输出逐人轨迹数组，
  `steps`/`run` 接受单条或数组（事件带 person 标记，混音合并所有人）。
  支持**亮/暗双极性**：暗色行人（亮景暗人）使用时序最大值背景的镜像
  模型，脚部 blob 用更严的强度阈值剔除行人拖在地上的软阴影；自动模式
  先跑亮色，亮色明显失败才切换暗色（亮主体视频在暗色模型下会产生
  "鬼影"轨迹，不能简单比较两遍得分）。
- **steps/**：落点 = "y 上升进入该帧，且未来 window 帧内无更高值"——
  即触地平台期的起始帧（脚落地后会驻留数帧，平台期是落点的本质特征；
  行量化上升沿的台阶则总有更高帧在后）。配 ±window 显著性过滤与同脚
  0.2 s 去抖；≤0.1 s 的可见度闪断（远距小脚的检测抖动）用线性插值桥接。
- **timecode/**：帧号 × 有理帧率（30000/1001 等）换算 SMPTE；drop-frame
  按标准规则在非整分跳过帧编号。
- **placement/ + wav/**：纯 MoonBit 采样级混音；SFX 线性插值重采样、
  落地强度映射增益（下限 0.35）、峰值超过 0.9 时整体向下归一。
- **audio/**：纯 MoonBit 音频脚步检测（20ms 帧能量、相对阈值、**局部基线
  超阈 + 陡峭上升沿**三重门：稳态噪声无局部超量被抑制，粉噪慢涌坡缓不
  触发上升沿，0.15s 去抖）与声画对齐——候选偏移按"配对数"打分、平局取
  更小偏移（步距混叠防呆），中位数残差精修；**落地网格密集（多人）时
  容差自动收紧到中位步距的 45%（下限 50ms）**，防止"每个 onset 在任意
  偏移都能配上"的评分饱和；再对配对残差做最小二乘拟合**漂移项**（双机
  录音时钟漂移 / PAL 提速 / 错采样率），累积不足一个容差（100ms）视为
  噪声不重采样。`align` 子命令对**全部人物**的落地配对（单人音轨对
  单人网格会把别人脚步的相位差配成假偏移）、提取原音轨、估计偏移+漂移、
  无漂移走采样级精确平移、有漂移走单次线性插值变速，重合成后保留原声
  音色。`align` 出口带**置信门**：匹配率 ≥60% 且中位|残差| ≤
  max(32%×容差, 30ms) 才动手修正，否则干净拒绝——错配音画（如慢走音频
  配快走视频会"配"出 280ms 假偏移、5/7 匹配）宁拒不修。wav 解析兼容
  ffmpeg 管道输出的流式 WAV（0xFFFFFFFF 占位 data 长度）。
- **fcpxml/**：FCPXML 1.8 导出——视频作为单条 asset-clip，每个落点一个
  marker（有理数时间 `帧×den/num` 秒，29.97 丢帧率帧号精确），Resolve/FCP
  导入后剪辑可在时间线上逐个微调；`mux` 走 ffmpeg `-c:v copy` 不重编码
  视频，音效轨转 AAC（原视频音轨被替换）。

## 已知边界（v0.2）

- 固定或缓慢移动的机位。正面/三分之四视角：**双脚需在画面内且离底边
  有上下摆动空间**（y 轴振荡是落点信号）；**侧视行走用 `detect
  --profile`**——追踪前脚 x 边缘的"跃进→驻留"，驻留起始即落点
  （步距驻留 > 搜索窗，平台期规则对 x 序列同样成立），左右脚按步态
  交替假定标注。合成侧视素材实测 6/6 步全部 ±0.5 帧命中、混音偏差
  ≤20ms。
- 多人（v0.4）：躯干列分组逐人跟踪，适用于**水平分开、不交叉遮挡**的
  行人；合成双人实测 33/37 步、身份正确（缺步集中在暖机期与次级人物
  轨迹缺帧，后者与 #6 同源）。交叉走位/互相遮挡仍不支持；align 用全部
  人物的落地配对混合音轨，密集网格靠自适应容差防混叠——实测三人同行
  + 粉噪（信噪约 3dB）仍精确恢复 0.4s 延迟（±3ms）；落地间隔压进
  ~110ms 以内的极密人群仍会歧义。
- 噪声（v0.4）：onset 检测按局部超量而非绝对电平工作——粉噪/白噪到
  脚步峰值的 ~70% 振幅（帧能量信噪比 ≥3dB）仍精确对齐，随机瞬态
  杂音（关门/碰撞）由配对评分天然隔离；噪声完全淹没脚步时**干净报错
  拒答**，不输出错误同步。
- 置信门的两类已知边界：① 音频混入大量非脚步瞬态（密集关门声/音乐/
  动效轨）时匹配率会被拉低而遭拒绝——**宁可拒不可错**，此时应先清理
  音轨再对齐；② 两人步频与相位几乎相同的错配在数学上与正确配对不可分
  （音轨落在任一网格上都同样"贴合"，匹配率高、残差小），属真歧义，
  任何门限都救不了。
- 真实素材实测（2026-09，两轮共 9 段免费图库素材均未跑通，如实记录）：
  第一轮 Mixkit 四段——脚被画框裁切、脚贴底边走、侧面视角（双脚水平
  重叠、无 y 摆动）、低角度硬阴影拖地。第二轮 Pexels 五段（ffprobe 确认
  CFR 后跑 `detect`→`steps`，域外镜头再按语义补 `--profile` 复测）：
  ① 正面走向镜头、双脚在画但离底边仅 5-8%（垂直摆幅 ~0.07）——5.4 s
  素材仅检出 1 步；② 正面走向镜头、深色裤/鞋与深灰路面灰度接近——
  足 blob 可见度均值 0.13，17.9 s 仅 1 步；③ 4K T 台走秀正对镜头——
  足部可见度 0.42、y 摆动存在仍 0 步：走向镜头的每一步人物都在放大，
  触地脚最低行持续下移，"未来 window 帧内无更高值"的平台期判据无法
  满足（整段与 2-7 s 裁段均 0 步）；④ 跑步机脚步特写——深色鞋与深色
  跑带不可分（可见度 0.05，0 步）；⑤ 海滩赤脚三分之二横穿、静态机位、
  双脚在画——烈日硬阴影使最低前景行钉死在地面线（y 恒 0.994），正面
  与 `--profile` 模式均 0 步。教训：图库实拍要同时满足"正面/三分之三
  ＋双脚在画＋离底边有摆动空间＋静态机位＋足部与地面灰度可分＋无拖地
  阴影＋人物尺度近似不变"极其困难，其中③说明"走向镜头导致人物持续
  放大"本身就是域外条件（合成原地行走素材不受影响，见 demo）。
- 开头约 0.3 s（背景暖机）内的落点不检测。
- WAV 输入仅支持未压缩 PCM 16/24-bit。
- 后续项：侧面视角 x 接触点追踪（#5）、远距小目标追踪（#6）、走向
  镜头时人物持续放大下的落点判据（#7）。

## 开发

```sh
moon check            # 快速类型检查
moon test             # 54 个黑盒快照测试
moon fmt && moon info # 提交前格式化并刷新 .mbti 接口
```

集成测试素材库（`examples/fixtures.sh`，CI 全量执行）：23 个公式自带
标准答案的场景——5 种帧率（含 29.97 丢帧时码断言）、慢/快步频、侧视
左右向、三人同行、暗色行人自动极性、2 倍尺度、晚入场（T=2 才入画）、
加噪、可变帧率拒绝、错配音画置信门拒绝（慢走音频+快走/侧视视频）。

包结构：`vision/`（解码 + 足部跟踪）、`timecode/`（SMPTE 数学）、`track/`
（轨迹模型）、`steps/`（落点检测）、`wav/`（RIFF 编解码）、`placement/`
（混音）、`internal/fsio/`（native FFI：文件 IO 与子进程管道）、
`cmd/moonfollow/`（CLI）、`fcpxml/`（Resolve/FCP 标记导出）、
`audio/`（音频脚步检测与声画对齐）。
